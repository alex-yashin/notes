# Деплой и доставка обновлений

Хостинг — **GitHub Pages**. Публикуется каталог `public/` как есть, без сборки.
Пользователям обновления доставляет service worker (`public/sw.js`) вместе с `public/js/update.js`.

## Как выпустить обновление

```bash
./tools/run-tests.sh              # тесты + php tools/release.php --check
php tools/release.php             # проставить версию = хеш содержимого public/
git add -A && git commit -m "…" && git push origin main
```

Workflow `.github/workflows/deploy.yml`:
1. проверяет `php tools/release.php --check`: если версию не проставили или `APP_SHELL` не совпадает с файлами,
   деплой падает;
2. публикует `public/` на Pages.

Если после изменения кода не запустить `tools/release.php`, `sw.js` не изменится и браузеры не узнают об обновлении.
Поэтому проверка встроена и в `run-tests.sh`, и в CI.

### Первичная настройка репозитория

1. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. Для своего домена: Settings → Pages → Custom domain. Включите «Enforce HTTPS»: service worker работает
   только по HTTPS.
3. Добавьте адрес сайта (`https://<user>.github.io` или свой домен) в:
   - CORS бакета S3 (`AllowedOrigin`, см. [CONFIGURATION.md](CONFIGURATION.md));
   - Redirect URI OAuth-приложений Яндекса и Google: `https://<user>.github.io/<repo>/` и `…/index.html`.

Приложение использует только относительные пути, поэтому работает и в подкаталоге `/<repo>/`.

## Как обновление доходит до пользователя

```
push → Pages обновил файлы
   ↓  (браузер проверяет sw.js при открытии, при возврате на вкладку и раз в час)
новый sw.js ≠ старый (CACHE_VERSION = хеш) → установка: весь APP_SHELL скачивается в новый кэш мимо HTTP-кэша
   ↓
полоса «Доступна новая версия — Обновить»          ← страница продолжает работать на старой версии целиком
   ↓ нажатие                                         (или: все вкладки закрыты → при следующем запуске новая)
SKIP_WAITING → новый SW активен, старый кэш удалён → страница перезагружается на новой версии
```

Гарантии (проверяются `./tools/update-e2e.sh`):
- **Нет смешения версий.** Все файлы оболочки, включая `index.html`, отдаются только из кэша своей версии.
  Файлы новой версии попадают в новый кэш целиком и заранее.
- **Нет устаревших файлов из HTTP-кэша.** GitHub Pages отдаёт файлы с `Cache-Control: max-age=600`, поэтому при
  установке SW качает файлы с `cache: 'reload'`. Сам `sw.js` браузер проверяет в обход HTTP-кэша: так делают
  браузеры по умолчанию (`updateViaCache: 'imports'`).
- **Ничего не теряется при перезагрузке.** Заметки сохраняются в IndexedDB сразу. Несохранённый текст из поля ввода
  перед переключением сохраняется как заметка.
- **Открытые вкладки не ломаются.** Старая вкладка работает на старой версии до нажатия «Обновить». Если новая версия
  меняет схему IndexedDB, старая вкладка закрывает соединение (`versionchange`) и просит перезагрузить страницу.
- Номер версии показан в настройках («Версия: …»).

GitHub Pages не позволяет задавать заголовки, поэтому `no-cache` для `sw.js` и `index.html` настроить нельзя.
Приложению это и не нужно, см. пункт про HTTP-кэш. Задержка до 10 минут на CDN Pages возможна:
обновление придёт при следующей проверке.

## Устройства с разными версиями

Пока пользователь не нажал «Обновить», его устройства могут работать на разных версиях и синхронизироваться
через одно хранилище.

- Формат файлов синхронизации версионирован (`"v"` в каждом файле, `FILE_FORMAT_VERSION` в `notes.js`).
- Старая версия, встретив файл **новее** своего формата, не читает и не перезаписывает его. Пользователь видит
  «…записан более новой версией приложения — обновите приложение на этом устройстве». Локальные изменения этого
  дня остаются помеченными и уйдут после обновления.
- Неизвестные поля записей сохраняются при слиянии. Добавлять новые **необязательные** поля можно без повышения
  `FILE_FORMAT_VERSION`: старые версии их не потеряют.
- Повышать `FILE_FORMAT_VERSION` нужно только при несовместимых изменениях. Вместе с этим обновите
  [PROTOCOL.md](PROTOCOL.md) и напишите миграцию чтения старого формата.

Порядок выкатки несовместимого формата:
1. **Релиз N:** код умеет читать новый формат, но пишет старый.
2. **Релиз N+1:** код начинает писать новый формат. К этому моменту большинство устройств уже обновлено до N,
   а остальные увидят подсказку «обновите приложение».

## Откат

Выложите предыдущее состояние `public/`: `git revert <commit>` → `push`. У отката тоже новый хеш содержимого,
поэтому клиенты получат его как обычное обновление с полосой «Обновить».

Откатывать безопасно, пока не менялся `FILE_FORMAT_VERSION`. Если менялся, старый код перестанет писать файлы
нового формата (см. выше), но данные не потеряются.

## Экстренный сброс (если в SW ошибка)

Если выпущенный `sw.js` сломан и страница не открывается, выпустите исправленный `sw.js`: браузер проверит его
в обход кэша при следующей навигации. Крайний вариант — выложить `sw.js`, который удаляет свои кэши
и снимает регистрацию:

```js
self.addEventListener('install', () => self.skipWaiting());
self.addEventListener('activate', (e) => e.waitUntil((async () => {
  for (const key of await caches.keys()) await caches.delete(key);
  await self.registration.unregister();
  for (const client of await self.clients.matchAll()) client.navigate(client.url);
})()));
```
