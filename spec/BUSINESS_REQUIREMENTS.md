# Бизнес-требования: «Заметки» — PWA для однострочных заметок с тегами

| Поле     | Значение |
|----------|----------|
| Статус   | Реализовано (v1). Интеграции с реальными S3, Яндекс Диском и Google Drive ещё не проверялись: нужны ключи и OAuth-приложения. |
| Источник | Постановка заказчика; уточнения по ходу разработки отмечены как **[уточнение]** |
| Связанные документы | [docs/PROTOCOL.md](../docs/PROTOCOL.md), [docs/CONFIGURATION.md](../docs/CONFIGURATION.md), [docs/I18N.md](../docs/I18N.md) |

Требования нумеруются `BR-xx`, критерии приёмки — `AC-xx.y`. При изменении требования обновляйте этот документ
вместе с кодом и тестами. Номера не переиспользуются.

## 1. Цель

Быстро фиксировать короткие мысли одной строкой, размечать их тегами и находить по тегу.
Заметки должны быть доступны без сети и синхронизироваться между устройствами пользователя через выбранное им
хранилище.

## 2. Пользователи и сценарии

Один пользователь, у которого есть одно или несколько устройств (телефон, ноутбук). Основные сценарии:

1. Открыть приложение, ввести мысль, отметить тегами, сохранить. На это должно уходить несколько секунд.
2. Просмотреть недавние заметки по дням.
3. Отфильтровать заметки по тегу.
4. Подключить облачное хранилище, чтобы заметки появились на другом устройстве.

## 3. Функциональные требования

### BR-01. Создание заметки

Заметка — одна строка текста с необязательным набором тегов.

- AC-01.1. На главном экране есть поле ввода текста и кнопка «Добавить». Сохранить можно и клавишей Enter.
- AC-01.7. Длинная строка в поле ввода переносится, а поле растёт вниз: заметка видна целиком без горизонтальной
  прокрутки. **[уточнение]**
  - Высота поля ограничена 40% высоты экрана, дальше внутри поля появляется прокрутка.
  - После сохранения поле снова в одну строку.
  - Кнопка отправки прижата к нижнему краю поля.
  - Заметка остаётся однострочной: Enter сохраняет, а переводы строк при вставке заменяются пробелами.
- AC-01.2. Текст приводится к одной строке: переводы строк и повторные пробелы схлопываются в один пробел,
  пробелы по краям обрезаются. Максимальная длина — 500 символов.
- AC-01.3. Пустую заметку (после обрезки пробелов) сохранить нельзя.
- AC-01.4. К заметке прикрепляются теги, выбранные в форме на момент сохранения (ноль, один или несколько).
- AC-01.5. После сохранения поле очищается и остаётся в фокусе. Выбранные теги сохраняются для следующей заметки.
- AC-01.6. Время создания фиксируется. День заметки — локальная дата устройства на момент создания.

### BR-02. Теги

- AC-02.1. Под полем ввода показан список доступных тегов. **Первым элементом** списка идёт кнопка «＋ тег»
  для создания нового тега.
- AC-02.2. Нажатие на тег в форме выбирает или снимает его (мультивыбор). **[уточнение: несколько тегов на заметку]**
  Выбранные теги одновременно задают фильтр списка, см. BR-04.
- AC-02.7. Кнопка отправки заметки — круглая, с иконкой стрелки и без текста. Название «Добавить» доступно
  в подсказке и для программ чтения с экрана. **[уточнение]**
- AC-02.3. Имя нового тега нормализуется:
  - начальные `#` отбрасываются;
  - пробелы внутри заменяются на `-`;
  - максимальная длина — 32 символа;
  - пустое имя не принимается.
- AC-02.4. Теги, отличающиеся только регистром, считаются одним тегом. Повторное создание существующего тега
  просто выбирает его.
- AC-02.5. Созданный тег сразу становится выбранным.
- AC-02.6. Теги отображаются с префиксом `#` и отсортированы по алфавиту по правилам языка интерфейса.

### BR-03. Список заметок по датам

- AC-03.1. Под формой выводится список заметок пользователя, **сгруппированный по дням**.
- AC-03.2. Дни идут от новых к старым (сверху «Сегодня»), заметки внутри дня — от старой к новой.
  **[уточнение: ранее внутри дня было от поздней к ранней]**
- AC-03.3. Заголовок группы: «Сегодня», «Вчера», иначе дата («12 марта»). Год показывается, только если он
  не текущий.
- AC-03.4. У каждой заметки показаны текст и её теги (под текстом).
  **[уточнение: вместо времени — порядковый номер в дне]**
  - Если за день несколько заметок, слева показан её порядковый номер в дне по времени создания:
    1 — самая ранняя. Номера сверху вниз идут по порядку: 1, 2, 3 …
  - Единственная заметка дня показывается без номера.
  - Номер не зависит от фильтра по тегам. Удалённые заметки не считаются.
  - Время создания доступно в подсказке номера.
- AC-03.6. Кнопка удаления заметки всегда находится справа, на уровне первой строки текста.
  Это верно и на узких (мобильных) экранах, и для многострочных заметок. **[уточнение]**
- AC-03.5. Если заметок нет, показывается подсказка «добавьте первую».

### BR-04. Фильтр по тегу

**[уточнение: форма добавления и фильтр совмещены; при нескольких тегах — заметки со всеми тегами (И).
Заменяет прежний вариант с отдельным фильтром по одному тегу и плашкой «Фильтр: #тег ✕»]**

- AC-04.1. Теги, выбранные в форме добавления, одновременно фильтруют список: остаются заметки,
  у которых есть **все** выбранные теги. Список показывает заметки, похожие на ту, что сейчас
  будет добавлена. Без выбранных тегов фильтра нет.
- AC-04.2. Нажатие на тег у заметки в списке выбирает или снимает этот тег в форме, с тем же эффектом.
  Выбранные теги подсвечиваются и в форме, и у заметок.
- AC-04.3. Когда выбран хотя бы один тег, в ряду тегов показывается «✕ сбросить». Оно снимает весь
  выбор и фильтр.
- AC-04.4. Если по выбранным тегам нет заметок, показывается «Нет заметок с выбранными тегами».

### BR-05. Удаление заметки

**[уточнение: добавлено при разработке как необходимое для синхронизации удалений]**

- AC-05.1. У заметки есть кнопка удаления. Перед удалением запрашивается подтверждение.
- AC-05.2. Удаление распространяется на другие устройства при синхронизации: удалённая заметка не
  «воскресает» (см. BR-10).

### BR-06. Настройки

- AC-06.1. Справа вверху расположена иконка шестерёнки. Нажатие открывает всплывающее окно (попап) настроек.
- AC-06.2. В настройках выбирается способ хранения заметок, в таком порядке:
  - только на этом устройстве (по умолчанию);
  - Яндекс Диск;
  - хранилище S3;
  - Google Drive.

  **[уточнение: Яндекс Диск выше S3; пункт «Регистрация» удалён, см. BR-09]**
- AC-06.3. Для выбранного способа показываются только относящиеся к нему поля и кнопки.
- AC-06.4. Есть кнопки «Сохранить» и «Синхронизировать» (ручной запуск). Показывается время последней
  синхронизации.
- AC-06.5. Для каждого провайдера есть способ отключиться («Выйти» или «Сбросить»).
- AC-06.6. Внизу попапа одной строкой и одним бледным шрифтом показаны версия приложения и ссылка
  на разработчика «Alex Yashin» (https://alex-yashin.ru/). Ссылка открывается в новой вкладке. **[уточнение]**

### BR-07. Хранилище S3

- AC-07.1. Пользователь вводит:
  - endpoint;
  - регион;
  - бакет;
  - префикс;
  - Access Key ID и Secret Access Key.
- AC-07.2. Поддерживаются S3-совместимые хранилища (AWS S3, Yandex Object Storage, MinIO): адресация бакета в пути
  или в поддомене.
- AC-07.3. Условную запись (защиту от одновременной записи) можно отключить для хранилищ, которые её не
  поддерживают.
- AC-07.4. Некорректный endpoint отклоняется при сохранении с понятным сообщением.
- AC-07.5. Если хранилище недоступно из браузера, пользователь видит причину и что исправить:
  - не настроен CORS — указывается origin приложения, требуемые методы и `ExposeHeader ETag`;
  - нет заголовка ETag — подсказка про `ExposeHeader ETag`;
  - ошибка хранилища — код и текст ответа.

  Полный текст доступен в подсказке и по нажатию на статус синхронизации.
  **[уточнение: вместо общего «ошибка синхронизации» показывать причину]**
- AC-07.6. Работает с S3-совместимыми реализациями, которые отличаются форматом ETag в `If-Match` (AWS — в кавычках,
  Ceph RGW / reg.ru — без кавычек). Формат определяется автоматически, от пользователя ничего не требуется.

### BR-08. Яндекс Диск и Google Drive

- AC-08.1. Подключение — через вход в аккаунт провайдера (OAuth) с возвратом в приложение.
- AC-08.2. Приложение получает доступ только к своей папке: папка приложения на Диске, `appDataFolder` в Drive.
  Остальные файлы пользователя ему недоступны.
- AC-08.3. Истёкший или отозванный доступ отображается как «нужен вход», данные на устройстве при этом не теряются.
- AC-08.4. Ответ авторизации принимается только при совпадении `state`. Токен сразу удаляется из адресной строки
  и истории браузера. Отказ в авторизации (`error`) показывается пользователю.

### BR-09. Регистрация — УДАЛЕНО

**[уточнение: режим «Регистрация» (внешний сервис + собственный API) удалён по решению заказчика]**

Номер не переиспользуется. Если в настройках устройства остался выбранным этот режим, приложение переключается
на «Только на этом устройстве». Заметки на устройстве сохраняются, сохранённые `client_id` и `client_secret` больше
не используются и удаляются при ближайшем сохранении настроек.

Требования к OAuth-возврату (проверка `state`, очистка адресной строки, показ ошибки) по-прежнему действуют
для Яндекс Диска и Google Drive, см. AC-08.4.

### BR-10. Синхронизация между устройствами

**[уточнение: синхронизацию вести с группировкой по датам или другим подходящим методом, чтобы минимизировать
конфликтующую запись с разных устройств]**

- AC-10.1. Данные в хранилище разбиты на файлы по дням создания заметок и отдельный файл тегов.
  Устройства пишут в основном в файл текущего дня, архив прошлых дней не переписывается.
- AC-10.2. Передаются только изменившиеся файлы: изменённые локально, изменённые на сервере или отсутствующие
  на сервере.
- AC-10.3. Одновременные изменения на разных устройствах **не теряются**. Слияние идёт по каждой заметке отдельно,
  и все устройства приходят к одинаковому результату.
- AC-10.4. Если хранилище поддерживает условную запись, одновременная запись одного файла обнаруживается,
  и слияние повторяется.
- AC-10.5. Синхронизация запускается автоматически:
  - вскоре после изменения;
  - при открытии приложения;
  - при возврате на вкладку;
  - при появлении сети;
  - периодически.

  Пользователь видит статус: идёт синхронизация, время последней синхронизации, ошибка, офлайн, нужен вход.
- AC-10.6. Одинаковые теги, созданные на разных устройствах, объединяются в один.
- AC-10.7. Некорректные или чужие данные в хранилище игнорируются и не ломают локальные данные.

### BR-11. Работа офлайн (PWA)

- AC-11.1. Приложение устанавливается как PWA: есть манифест и иконки.
- AC-11.2. После первого открытия приложение запускается и работает без сети. Заметки создаются, фильтруются
  и удаляются локально.
- AC-11.3. Накопленные офлайн изменения отправляются при появлении сети.
- AC-11.4. Выбор «только на этом устройстве» полностью исключает сетевые запросы с данными пользователя.

### BR-12. Локализация

**[уточнение: русский и английский, выбор по языку браузера, fallback — английский]**

- AC-12.1. Интерфейс доступен на русском и английском. Это касается всех надписей, подсказок, сообщений об ошибках,
  а также форматов даты и времени.
- AC-12.2. Язык выбирается автоматически: первый поддерживаемый из предпочтительных языков браузера.
  Если подходящего нет, используется английский.
- AC-12.3. Ручного переключателя языка нет.
- AC-12.4. Смена языка интерфейса не влияет на данные: теги с разных устройств синхронизируются независимо
  от языка.

### BR-13. Доставка обновлений

**[уточнение: применение по кнопке «Обновить», версия через tools/release.php, хостинг — GitHub Pages]**

- AC-13.1. После публикации новой версии приложение обнаруживает её само:
  - при открытии;
  - при возврате на вкладку;
  - не реже раза в час, пока приложение открыто.
- AC-13.2. Новая версия скачивается в фоне. Пользователь видит полосу «Доступна новая версия — Обновить».
  Нажатие переключает приложение на новую версию. Без нажатия новая версия включается при следующем
  запуске, когда все вкладки закрыты.
- AC-13.3. До переключения приложение целиком работает на старой версии, после — целиком на новой. Смешение
  файлов разных версий исключено.
- AC-13.4. При обновлении не теряются ни заметки, ни набранный, но не сохранённый текст.
- AC-13.5. Устройство со старой версией не портит данные, записанные более новой версией. Файлы нового формата
  оно не перезаписывает и просит обновить приложение. Неизвестные поля записей сохраняются.
- AC-13.6. Номер установленной версии виден в настройках.
- AC-13.7. Откат на предыдущую версию доставляется пользователям так же, как обычное обновление.

## 4. Нефункциональные требования

| ID     | Требование |
|--------|------------|
| NFR-01 | Приватность: данные хранятся только на устройстве и в хранилище, выбранном пользователем. Собственного сервера у приложения нет. |
| NFR-02 | Секреты (ключи S3, OAuth-токены) хранятся только локально на устройстве и не попадают в URL после обработки возврата. |
| NFR-03 | Без сборки и внешних зависимостей: сайт — статический каталог `public/`, деплоится как есть. |
| NFR-04 | Целевые браузеры — актуальные Chromium, Firefox и Safari. Автотестами проверяется только Chromium, Firefox и Safari нужно проверять вручную. Адаптивная вёрстка для телефона и десктопа, светлая и тёмная тема. |
| NFR-05 | Доступность: у интерактивных элементов без текста есть `aria-label`, статус синхронизации объявляется (`aria-live`). |
| NFR-06 | Обратная совместимость формата данных синхронизации: новые версии читают данные, записанные старыми. |

## 5. Вне рамок v1

- Редактирование текста существующей заметки.
- Переименование и удаление тегов через интерфейс.
- Полнотекстовый поиск; фильтр «любой из тегов» (ИЛИ) — сейчас только «все теги» (И), см. BR-04.
- Совместный доступ нескольких пользователей к одним заметкам.
- Шифрование данных на стороне клиента.
- Собственный сервер синхронизации (режим «Регистрация» удалён, см. BR-09).
