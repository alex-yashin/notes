# AGENTS.md

Инструкции для AI-агентов, работающих с этим репозиторием.

## О проекте

PWA для однострочных заметок с тегами: список по дням, фильтр по тегу, офлайн-режим, синхронизация через
S3, Яндекс Диск, Google Drive или собственный API (режим «Регистрация»). Интерфейс на русском и английском.

- **Требования:** `spec/BUSINESS_REQUIREMENTS.md` (BR-xx / AC-xx.y) — источник истины о поведении.
- **Техническая документация:** `docs/`.

## Структура

```
public/   корень сайта — только то, что отдаётся браузеру; деплоится как есть
tests/    браузерные тесты (tests.html, tests.js), по HTTP доступны как /tests/*
tools/    dev-сервер, mock-API, раннеры тестов, генератор иконок (PHP 7.4 / bash)
docs/     PROTOCOL.md, CONFIGURATION.md, I18N.md, DEVELOPMENT.md
spec/     бизнес-требования
```

Ключевые модули (`public/js/`):
- `notes.js` — доменная логика и CRDT-слияние, чистые функции;
- `sync/engine.js` — движок синхронизации;
- `sync/*.js` — адаптеры хранилищ;
- `repo.js`, `db.js` — IndexedDB;
- `settings.js` — настройки и OAuth;
- `i18n.js` — локализация;
- `app.js` — UI.

## Команды

```bash
php -S localhost:8000 tools/dev-server.php   # приложение + тесты (/tests/tests.html)
php -S localhost:8081 tools/mock-api.php     # dev-сервис регистрации и API
./tools/run-tests.sh                         # все тесты; ожидается "PASS Tests: N, passed: N, failed: 0"
./tools/render-check.sh ru-RU                # заголовок вкладки при языке браузера (ожидается «Заметки»)
php tools/release.php                        # проставить версию релиза после ЛЮБОЙ правки в public/
./tools/update-e2e.sh                        # E2E доставки обновлений (ожидается "PASS update-e2e")
./tools/ui-e2e.sh                            # E2E главного экрана при правках UI (ожидается "PASS ui-e2e")
php tools/make-icons.php                     # пересобрать PNG-иконки в public/icons
php -l tools/<file>.php                      # проверка синтаксиса PHP
```

Тесты требуют запущенного dev-сервера на `:8000`. **Перед тем как сообщать о готовности, обязательно запустите
`./tools/run-tests.sh`** и приведите его вывод.

## Правила кода

### Общие
- Никаких сборщиков, npm-зависимостей и CDN. Только нативные ES-модули и Web API: IndexedDB, WebCrypto, fetch,
  `<dialog>`.
- В `public/` лежит только то, что нужно браузеру. Тесты — в `tests/`, служебные скрипты — в `tools/`,
  документы — в `docs/` и `spec/`.
- Литералы (URL, лимиты, таймауты, ключи хранилищ) выносятся в именованные константы. Настройки окружения —
  в `public/js/config.js`.
- Не опирайтесь на API, которые браузер отключает по http:// не с localhost, без запасного варианта:
  - для id и `state` — только `newId()` из `notes.js`, не `crypto.randomUUID()`;
  - для `crypto.subtle` — только через `sigv4.js`, который бросает понятную `InsecureContextError`.

  Проверка: `./tools/secure-context-check.sh`.
- Комментарии и логи в коде — на русском, как в существующем коде. Логи с префиксом-тегом:
  `[sync]`, `[settings]`, `[i18n]`, `[sw]`.

### Локализация
- Любая строка, которую видит пользователь, идёт через `t('key')` из `i18n.js` или через `data-i18n*`
  в разметке. Ключ добавляется **в оба словаря** (`en` и `ru`) с одинаковыми плейсхолдерами `{…}`.
  Это проверяет тест.
- Дефолтные тексты в `index.html` — английские.
- Даты, время и сортировка — через `getLocale()`.
- Сообщения `console.*` не локализуются.

### Синхронизация и данные — не ломать совместимость
- Формат файлов (`day-YYYY-MM-DD.json`, `tags.json`, `{"records":[…],"v":1}`), правила LWW-слияния и tombstones
  описаны в `docs/PROTOCOL.md`. Данные уже лежат в хранилищах пользователей. Изменение формата требует
  повышения `FILE_FORMAT_VERSION`, миграции и обновления документа.
- Удаление — только через `tombstone()`. Физически удалять записи нельзя: иначе они «воскреснут» с других устройств.
- Любая запись локально меняет `updatedAt` и помечает файл «грязным»: используйте `repo.saveNote/saveTag`.
- `tagIdFromName` намеренно использует `toLowerCase()` без локали: id тега не должен зависеть от языка устройства.
- Слияние должно оставаться коммутативным, ассоциативным и идемпотентным. Тесты на это есть, не удаляйте их.
- Новый адаптер хранилища реализует `list()` / `get(name)` / `put(name, text, version)` и бросает `ConflictError`
  при устаревшей версии и `AuthError` при 401.

### Service worker и релизы (см. `docs/DEPLOY.md`)
- После любой правки в `public/` выполните `php tools/release.php`. Он ставит `CACHE_VERSION` и `APP_VERSION`
  по хешу содержимого. Вручную их не редактируйте. `run-tests.sh` и CI падают, если версия устарела.
- При добавлении, удалении или переименовании файлов в `public/` обновите `APP_SHELL` в `public/sw.js`:
  `release.php --check` покажет расхождение.
- Не добавляйте в SW `skipWaiting()` при установке и фоновое обновление кэша отдельных файлов: это смешивает
  версии. Переключение идёт только по кнопке «Обновить» или после закрытия всех вкладок.
- При изменении `sw.js` или `update.js` запустите `./tools/update-e2e.sh`.
- Изменение схемы IndexedDB: поднимите `DB_VERSION` и добавьте ветку `if (oldVersion < N)` в `onupgradeneeded`.
  Пересоздавать хранилища нельзя: в них данные пользователей.
- Новые поля записей — только необязательные, без повышения `FILE_FORMAT_VERSION`. Несовместимый формат
  выкатывается в два релиза: сначала чтение, потом запись (`docs/DEPLOY.md`).

### Безопасность
- Секреты (ключи S3, токены, `client_secret`) хранятся только в `localStorage` устройства. Они не логируются
  и не остаются в URL: после OAuth или регистрации адрес очищается через `history.replaceState`.
- Ответы OAuth и регистрации принимаются только при совпадении `state`.
- Данные из удалённого хранилища считаются недоверенными: фильтруются через `isValidRecord` / `belongsToFile`
  и выводятся только через `textContent`. `innerHTML` с пользовательскими данными запрещён.

### PHP (`tools/`)
- Совместимость с **PHP 7.4**: `declare(strict_types=1)`, без `match`, enum, `readonly` и nullsafe-оператора `?->`.

## Тесты

- Новая логика в `notes.js`, `sync/*` или `i18n.js` сопровождается тестом в `tests/tests.js`.
  Фреймворк — `test(name, fn)`, `assert`, `assertEqual`.
- Модули приложения импортируются из тестов абсолютными путями от корня сайта (`/js/...`).
- Для синхронизации есть in-memory `memoryRemote()` / `memoryRepo()`, для языка — `withLanguage(lang, fn)`.
- Тесты не должны оставлять данные в IndexedDB: уберите за собой через tombstone или используйте in-memory репозиторий.

## Окружение и известные особенности

- Node.js в окружении нет. Chromium — snap-версия:
  - `--dump-dom` не поддерживает IndexedDB, поэтому раннеры работают через DevTools-порт;
  - браузер закрывается только через `tools/cdp-close.php`, `pkill` не работает (AppArmor);
  - профиль должен лежать в `~/snap/chromium/common/`.
- Git-репозиторий не инициализирован. Перемещения файлов — обычным `mv`.

## Чего не делать

- Не добавлять зависимости, сборку, TypeScript или фреймворки без явной просьбы.
- Не менять протокол синхронизации и формат данных без обновления `docs/PROTOCOL.md` и миграции.
- Не класть в `public/` тесты, документацию и служебные скрипты.
- Не менять требования в `spec/` молча. Если задача меняет поведение, обновите соответствующий BR/AC
  и отметьте это в ответе.
